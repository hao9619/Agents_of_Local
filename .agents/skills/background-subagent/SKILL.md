# 后台子代理任务

在用户明确要求后台执行、且当前会话允许委派时，用子代理管理长期任务，取得启动证据后返回主线程回复，供用户稍后查询或停止。阅读、评审或修改本文不构成启动后台任务的请求。

## 适用能力与模型选择

- 先核对当前环境的子代理工具及运行方式。只有支持主线程回复后继续执行的环境才能承担后台任务；未确认时明确说明运行保障尚未验证，不凭 `spawn_agent` 可用就承诺持续执行。能力不可用时如实说明，不把普通同步执行说成后台启动。
- 工具名称、参数和权限以当前会话定义为准。技能不授予额外文件、网络、算力或外部操作权限。监控默认只观察并在获准位置记录；修复、重启服务和外部通知须已有相应授权。
- 模型与推理强度遵循[子代理模型选择](codex-subagent-model-selection.md)。规则明确的状态检查可以使用轻量模型；根因分析、实验判断和代码修改按实际难度选择。用户指定优先，不静默替换。
- 通常使用 `fork_turns: "none"` 并显式交接上下文；依赖大量前文时可继承会话，按工具能力处理模型覆盖。子代理默认不继续委派。
- 任务目录与长期报告遵循[文档编写与维护规范](documentation.md)。缺少配套文件时说明缺项，依照当前工具能力和明确用户要求处理，不虚构已读取的规则。

## 确定任务边界

创建后台辅助会话前，执行[主会话与辅助会话的监管](codex-subagent-model-selection.md)规则：说明任务、范围、资源与监管建议，等待用户选择。用户要求“后台执行”但尚未选择监管方式时，不能据此直接创建辅助会话。选择用户监管时，准备交接，由用户创建或接管；以下自动创建流程仅适用于已选择 Codex 监管的任务。

区分两类任务，并从已有会话提取目标、成功条件、结束条件、资源限制和允许的动作：

| 类型 | 必须明确的执行依据 | 完成判定 |
| --- | --- | --- |
| 周期监控或等待条件 | 监控对象、检查方式、间隔、目标条件及截止时间 | 实际观测满足目标条件；到期未满足则超时。用户要求持续观察时，按其停止要求执行 |
| 一次性长任务 | 命令或阶段计划、工作目录、输入和源码版本、输出位置、设备及时间或资源上限 | 必要阶段实际结束，并核对退出码和预期结果；创建进程、出现日志或某个中间阶段通过均不足以判定完成 |

监控缺少常规参数时可明示有限默认值，例如每 60 秒检查、最多运行 1 小时。一次性任务的期限与资源按任务规模和已有授权确定，不套用监控默认期限，也不自行扩大实验范围。明确期限到达后，停止继续派发工作，按约定结束本任务的执行进程并核查清理结果；只有监控职责时，不停止被观察的外部作业。

派发前核对已有任务目录、活动代理和相关进程，避免重复下载、重复训练或重复监控。主代理统一协调共享文件和 GPU/NPU 等资源；已有明确授权无需重复询问。

## 启动与确认

1. 在获准写入的工作目录下创建独立任务目录，如 `.background-tasks/YYYY-MM-DD-主题-唯一后缀/`。派发前确定真实任务 ID 和日志绝对路径，不留下待子代理推断的占位符。用户指定保存位置时遵从；需要后续查询时使用持久位置，不仅依赖临时目录。
2. 主代理写入 `task.json`，记录任务 ID、类型、目标、工作目录、参数、创建时间、期限或停止条件、资源和权限边界、日志位置，以及监管者、用户已确认的监管选择与时间。用当前环境的 `spawn_agent` 创建一个子代理，随后记录实际返回的完整代理标识及模型配置；继承配置无法确认具体值时如实标明，不猜测。将任务目录链接到本项目现有状态入口。
3. 任务说明包含适用规则、最新上下文、允许修改的范围、执行或采样方法、成功与停止条件、日志目录，以及“首次实际检查或执行后立即确认，结束时写明结果”的要求。
4. 子代理维护 `status.json` 和追加式 `events.jsonl`：记录 UTC 时间、状态、当前阶段、最近实际检查或进展、错误与证据位置；存在执行进程时记录所属主机、PID/作业 ID、启动时间和任务关联。状态文件采用完整替换等方式避免读到半份内容；日志不保存凭据，并限制持续监控的日志增长。
5. 监控取得首次实际检查结果后，才报告“监控已启动”；一次性任务取得真实执行或已完成的证据后，报告对应状态。只有代理创建返回值时，报告“已创建，等待启动确认”。启动等待应有界；不能确认时说明已知状态和证据缺口，不伪称成功或额外启动副本。
6. 取得启动确认后即可结束主线程回复，不等待整个长期任务。结束结果区分成功、超时、失败和用户停止；需要输入或审批时标为受阻；发现执行中断或状态无法确认时保留该事实，不伪装为持续运行。

## 执行、采样与证据

- 规则固定的周期采样可由子代理管理可停止的脚本，减少重复模型调用。一次检查设置合理超时；失败按既定次数或期限重试，记录原因，避免无间隔或无限重试。
- 一次性任务保留输入和版本、阶段日志、退出码与输出路径。后台运行方式须匹配本地或远程环境；未确认会话依赖已解除时，不承诺关闭终端或客户端后任务仍会继续。
- 脚本心跳、代理状态和任务结果分别核查。脚本时间戳只说明脚本有活动；证明代理继续推进需要新的代理调用或阶段操作证据；判断任务完成还需实际结果。脚本不能仅靠写入日志就保证自动唤醒模型。
- 没有新事件的监控仍按约定更新最近检查时间。长命令暂时无输出时核查进程、工具状态或阶段记录，不凭日志安静就断言失败，也不把主线程查询时间写成最近成功检查时间。
- 主代理维护任务元数据，执行者维护状态和事件。停止或恢复时协调写入责任，避免旧代理和新代理同时覆盖状态。发生重复或矛盾记录时保留证据，先核实实际执行者。

## 启动后告知用户

回复包含任务 ID、当前状态、首次检查或执行的证据、监控频率或当前阶段、停止条件、日志位置，以及“稍后在本会话询问进度或要求停止”的用法。根据实际记录填写，不把示例当成已经发生的事实。

首次启动时简要说明适用的运行与资源条件，同一任务后续查询不重复整段提示，除非条件发生变化：

- 承载代理和作业的实际运行环境需要保持可用。关闭客户端后是否继续，取决于客户端、后端和进程的生命周期；不保证所有退出方式都有效。若作业运行在独立远端，代理失联不代表远端作业已停止，应分别检查。
- 休眠、断网、权限请求或环境退出可能阻塞或中断工作。后台代理会使用模型额度，脚本和作业也会消耗相应资源。
- 后续可在本会话请求查询；不承诺自动唤醒主线程、系统弹窗、外部通知或跨重启自动恢复。通知能力须实际存在且获准使用。

这些说明不构成额外确认步骤。已获授权且能力具备时直接执行，确有缺失信息或权限时只暂停受影响部分。

## 后续查询、停止与恢复

| 用户意图 | 操作 |
| --- | --- |
| 查询进度 | 先读任务元数据、状态、日志时间和实际结果，再用当前环境的代理查询工具核对状态；必要时才联系代理。报告最近检查或进展时间及证据，指出过期或矛盾信息，不凭 `running` 标签声称任务正常。 |
| 验证退出期间是否继续 | 先读取日志，不先恢复、唤醒或派发任务。比较退出前后时间以及新检查／阶段记录，说明证据支持的是脚本存活还是 agent 持续推进。 |
| 停止任务 | 按用户要求停止指定任务，不重复索要确认。协调执行者停止工作，必要时中断代理；核对其采样脚本、执行进程及子进程是否已退出。终止前确认所属主机、启动时间和任务关联，避免仅凭旧 PID 误杀其他任务。只观察外部作业的任务仅停止监控。无法确认清理时标为停止待核实，不宣称已全部停止。 |
| 恢复中断任务 | 先检查原代理、脚本及远程作业是否仍在运行，避免重复执行。已有继续授权时按原目标和剩余期限恢复；期限已过则说明情况，不自行续期。每次恢复记录独立 attempt、新旧代理标识及延续的进程，保留旧日志，不把恢复记录描述为从未中断。 |

工具进程的 `session_id` 可能只在所属代理内有效。主线程无法直接轮询时，读取共享日志或让所属代理查询，不把跨代理的 `Unknown process id` 当作任务已经退出。

恢复原有执行者且授权范围不变时沿用既有监管选择；需要新建替代辅助会话或改变监管者时，先告知用户并取得选择，再记录新旧执行者的交接。停止、受阻、恢复和结束时同步项目状态入口，避免其他主会话重复启动任务。

用户要求后台执行且环境支持时，主线程回复结束不主动停止仍在执行的任务。最终报告列出实际结果、完成时间、证据位置和残留进程情况；不为查询状态默认重跑作业或补做任务范围外实验。

能力与权限边界可参考 [OpenAI 官方子代理说明](https://learn.chatgpt.com/docs/agent-configuration/subagents?surface=app)。具体客户端的后台持续执行、通知和恢复能力仍以当前环境的说明与实际证据为准。
