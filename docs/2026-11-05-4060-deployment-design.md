# RTX 4060 本机部署设计

日期：2026-11-05。状态：设计已获用户确认并已实施；实际状态见根 README。原设计端口 11434 在实施时因已有服务改为 11435。

## 目标与范围

在本机 Windows 11 / RTX 4060 Laptop 8GB 上，通过 Cursor 的 Continue 扩展调用本地模型，完成一次读文件、修改文件的小任务。保留简单可修改的配置、部署和检查脚本，方便学习和通过 Git 复现。此次不部署 Ryzen 电脑，不修改模型神经网络或训练权重。

## 方案取舍

- 用户选择：Ollama + Continue。直接使用回环地址接入，配置层次少，适合学习。
- 曾考虑 Cursor 自带 Agent + 自定义 API：接入路由与兼容性需要另行验证，不纳入此次实施。
- 另一候选为 llama.cpp + Continue：运行参数更细，但二进制、模型模板和服务参数需要自行管理，首次部署采用 Ollama。

## 实施选择

以下是 Codex 提议的默认值，尚非实测结论。

- 基础模型：`qwen3.5:4b-q4_K_M`，官方标签约 3.3GB；创建本地别名 `local-coder-4060`。
- 上下文 8192 tokens、单次输出上限 2048、温度 0.2。先以实际显存占用和工具调用结果验收，再考虑增加上下文。
- Ollama 仅监听 `127.0.0.1:11434`。模型下载需要网络，运行时推理使用本机服务。
- 优先使用官方 Windows 独立压缩包，将运行文件、模型和日志放在项目内被忽略的 `.local/`，避免模型权重进入 Git；启动脚本显式设置模型目录和监听地址。如压缩包方案不可用，再说明原因并使用官方安装器。
- Continue 配置模板保存在 `continue/config.yaml`；实际用户配置安装前检查现有文件，已有配置先备份，不直接覆盖。安装扩展及写用户目录可能需要执行环境授权。
- 项目文件：`profiles/rtx-4060/Modelfile`、`scripts/setup.ps1`、`scripts/start.ps1`、`scripts/check.ps1`、简短 Python API 调用示例、README、忽略规则和验证记录。配置注明上下文、输出、提示词、工具各自的作用。
- 使用根目录 README 作为状态入口，保留实际版本、模型摘要、证据与后续步骤。本次不由 Agent 暂存、提交或推送；当前目录尚非 Git 仓库。

## 验收和故障处理

1. 记录 Ollama 版本、模型标签及摘要；服务 API 可访问，实际模型可生成回答。
2. 检查运行时 GPU 使用和显存占用，不以模型下载成功代替 GPU 推理成功。
3. 用一个无副作用工具验证模型能返回结构正确的工具调用，并接收工具结果完成回答。
4. 在 Cursor Continue 中选择模型，完成独立示例目录内的读文件和修改文件任务；若 UI 无法自动操作，明确区分 API 已验证和编辑器待验证。
5. 如显存不足，先降低上下文并重测；如工具调用失败，保留失败证据，核对版本、模板和请求参数后再调整，不仅通过声明 `tool_use` 就认定支持。

4B 模型的复杂编码能力是待实测限制；一次小任务成功不代表复杂项目的 Agent 能力。
